# i18n PT-BR / English Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Scanline auto-detects the machine's OS locale on first run and renders its UI in Portuguese or English, with a manual override in Settings that persists.

**Architecture:** Native OS locale comes from the Tauri `plugin-os` `locale()` API. A hand-rolled `i18n.ts` module holds two type-checked dictionaries (`en` is the source of truth; `pt` must mirror its keys) and a synchronous `t(key)` lookup. Boot order: load config → resolve locale (override or OS detect) → set active dict → render. Manual language change persists to `scanline.json` and triggers `location.reload()`; the existing session-restore path re-hydrates panes.

**Tech Stack:** TypeScript, Vite, Vitest, Tauri v2 (Rust), `@tauri-apps/plugin-os`.

const DICTS: Record<Lang, Messages> = { en, pt };
let active: Messages = en;

/** Synchronous lookup in the active dictionary. */
export function t<K extends keyof Messages>(key: K): Messages[K] {
  return active[key];
}

/** Set the active dictionary. Call before any t()-backed render. */
export function setLocale(lang: Lang): void {
  active = DICTS[lang];
}

/** Map an OS locale string (e.g. "pt-BR") to a supported language. */
export function mapLocale(raw: string | null | undefined): Lang {
  if (!raw) return "en";
  return raw.toLowerCase().startsWith("pt") ? "pt" : "en";
}

/** Read the OS locale natively via plugin-os and map it. Never throws. */
export async function detectOsLocale(): Promise<Lang> {
  try {
    return mapLocale(await locale());
  } catch {
    return "en";
  }
}

/** Resolve the language: explicit override wins, else OS auto-detect. */
export async function resolveLocale(language: "auto" | Lang): Promise<Lang> {
  if (language === "pt" || language === "en") return language;
  return detectOsLocale();
}
